# 640×480 本地骨架实测与回滚交付

2026-10-28，机器人 RK3588 / Android 12，后置相机；服务端为 Apple M1 的 CPU 推理。客户端 1.2.0、服务端 1.1.0。此结果不代表 Jetson、其他网络或临床准确率。

## 结论与口径

日常模式的回传视频字节与解码帧增量均为 0，服务端绘制耗时为 0；保留视频上传、业务结果与骨架数据。六动作固定输入共 3,432 帧的关键点、阶段、计数与合格判定一致，浮点绝对误差容限 1e-6。

真人按用户要求仅测摩擦手背、握拳伸展。旧版 12 段（本地/远端×两动作×3），新版首测 18 段（本地/骨架/诊断×两动作×3），另有摩擦手背骨架复测 3 段，共 33 段。每段预热 15 秒，取其后 30 秒；早期 60 秒基线保留原始数据，比较只取前 30 秒。采集请求 640×480、15 FPS，设备实际约 25 FPS，未提高采集规格。

下表为三个独立采样窗口的中位数。服务端 FPS 直接用逐帧完成数除实际经过时间；界面报告的短区间 FPS 另保留于 CSV，不能以瞬时 FPS 倒数当作端到端延迟。其余列为三段各自中位数的中位数。每段指标的中位数、P95、最小/最大值完整保存在 metrics.csv；未将“三个 P95 的 P95”当作合并 P95。

## 验证与限制

- 六个固定视频共 3,432 帧前后一致：rub 0、fist 8、stretch 0、cup 0、abduction 0、press 4。这些是该固定输入的回归输出，不是准确率或真人标准次数。真人未记录人工逐次真值，不比较真人计数准确率。
- 服务端动作/UI、推理、RTC、业务、账号/计划/反馈、患者密码、业务 RTC、教学、结构和骨架序列化/权限回归通过。RTC 同时覆盖骨架通道缓冲积压时跳过更新，而可靠停止与汇总继续完成。
- Android 骨架仪器测试覆盖横竖比例、留白、镜像、旧序号、错会话、过期和预测手点；真实训练检查普通模式无回传轨、切换不重连不重置、诊断开关复位及 PNG 为 640×480。
- 最终 APK 对应源码的五项仪器回归完整通过（OK 5 tests）：两项骨架测试、切后台保留部分记录、两动作完整训练、患者权限与不适退出。正式签名构建、测试包构建和现有单元测试通过。性能采样后仅调整消息大小检查的分配顺序及显示无障碍说明，未改变视频、绘制或识别流程。
- 部分仪器测试在方法完成、数据与训练结果保存后被系统以 USER REQUESTED 从外部强停，运行器报告 Process crashed。旧/新两版均出现，无对应 Java/native 崩溃堆栈，触发方尚未确认。这些段可用于完整采样比较，不能算完整 JUnit 通过。原始 runner/exit-info 留存。
- before-fist-2-local 的温度系列不完整，其 App 指标和结果完整。初次复测因退出 IDE 同时关闭 ADB 而未启动；恢复连接后以独立 after-retest 标签重测三段，失败启动没有进入统计。
- 未更换模型或调整六动作算法，数据库 schema 保持 3；关键点与性能采样不写患者业务库。未执行 Jetson、高清档、长时间稳定性或全部六动作真人性能采样。既有旧 Android API 兼容 Lint 问题不在本轮修复。

## 文件、部署与回滚

原始指标与汇总位于本次交付 raw-metrics.zip，APK 与 SHA-256 位于 delivery。ZIP 只收录测试指标、固定视频回归和验证记录，不含 App 登录备份、患者库、签名密钥或摄像头原图。

服务端与 App 需配套更新。原 8000 端口仍运行旧版 1.0.0，本次独立测试使用 18121 和临时库；没有替换正式库或重启正式服务。仅更新源码不会改变原进程，新 App 开始训练前会提示旧服务升级。部署/下一次诊断开关/回滚详见 [local_skeleton.md](local_skeleton.md)。

回滚包使用基线源码与原签名，仅将 versionCode 提升为 3，支持从新版 code 2 覆盖回滚；不卸载、不清除数据。基线服务与新版服务均为 schema 3，显示回滚无需覆盖现有业务记录。回滚后再次升级需构建 code 大于 3 的 APK。本次不推送 GitHub。
